# Chronos Mobile

Локальный планировщик на Expo SDK 58. Zustand сохраняет цели, фиксированные блоки, окна энергии, расписание и историю выполненных сессий в AsyncStorage.

- **Сегодня / Неделя** показывает таймлайн на семь дней. Сессии можно отметить выполненными, закрепить или запустить с таймером фокуса. Таймер сохраняется между запусками, поддерживает паузу и прибавление 15 минут. Засчитываются полные отработанные минуты. Форс-мажор переносит незакреплённые сессии, попавшие в недоступный интервал от текущего времени.
- **Цели** показывает прогресс и прогноз по текущему семидневному плану. Здесь можно добавлять, редактировать и удалять цели.
- **Режим и энергия** позволяет управлять фиксированными блоками и окнами энергии, включить локальные напоминания на телефоне, экспортировать JSON или вернуть демо-данные. Напоминания планируются за 10 минут, время доставки может зависеть от настроек ОС.
- **Аналитика** показывает выполненное время, график по целям, активность по часам и диагностику семидневного плана. Автооптимизация улучшает энергетическое совпадение и распределение нагрузки с учётом закреплённых слотов.

## Запуск

Используйте Node.js 22.13+ (ветка 22) или 24.3+ (ветка 24).

```bash
npm ci
npm start
```

Откройте QR-код в Expo Go, совместимом с Expo SDK 58. Для LAN-запуска телефон должен иметь доступ к компьютеру с Metro. Если доступа по LAN нет, попробуйте `npm start -- --tunnel` в сети, которая разрешает туннель Expo. Для веб-версии используйте `npm run web`.

```bash
npm run typecheck
npm test
```

## Солвер

`generateSchedule(params)` возвращает объект с `sessions`, исходными `params` и `unscheduledMinutes` по каждой цели. Семь календарных дней отсчитываются от `startDateISO` включительно. По умолчанию используется локальная дата устройства. Все даты имеют формат `YYYY-MM-DD`, дедлайн включает весь указанный день. Время задаётся минутами от полуночи, а блоки через полночь разделяются на два интервала.

Энергетические окна повторяются каждый день. Совпадение по уровню даёт 1, разница в один уровень даёт 0,5, разница в два уровня или отсутствие окна дают 0. Оценка сессии усредняется по её минутам. Локальный поиск за 500 итераций пытается улучшить суммарное совпадение без изменения длительности сессий. Фиксированные блоки, закреплённые и выполненные сессии служат ограничениями для нового расписания. Интервалы форс-мажора также учитываются при последующих пересчётах.

`rescheduleOnDisruption(schedule, dateISO, fromMinute)` считает остаток указанного дня недоступным. Для более короткого сбоя передайте четвёртым аргументом `resumeMinute`. Солвер переносит пересекающиеся незакреплённые сессии в ближайшее подходящее окно, соблюдая буфер, дедлайн и исходный горизонт. Если места нет, минуты попадают в `unscheduledMinutes`.

## Первый запуск и What‑If

При первом запуске Chronos предложит личный план с базовыми окнами сна и энергии или демо-план с примерами целей. Можно завершить настройку позже в разделах «Цели» и «Режим и Энергия». Ранее сохранённое расписание откроется сразу.

В разделе «Цели» откройте What‑If, заполните параметры гипотетической цели и нажмите «Рассчитать сценарий». Chronos пересчитает семидневный план с учётом действующих ограничений, покажет, успевает ли новая цель к дедлайну, и сравнит даты завершения остальных целей. Сценарий доступен только для просмотра.

## Офлайн-PWA

```bash
npm run build:web
```

Разместите содержимое `dist/` в корне сайта по HTTPS. Для прямых переходов на маршруты приложения настройте отдачу `index.html` для URL без соответствующего файла. При первом открытии нужен интернет, чтобы service worker загрузил ресурсы приложения. После этого Chronos можно открывать и использовать офлайн. Расписание хранится в браузере текущего устройства. Для локальной проверки можно раздать `dist/` на localhost.

## Android APK через EAS

Войдите в EAS и привяжите репозиторий к своему проекту Expo. Профиль `preview` создаёт APK для внутреннего распространения.

```bash
npx eas-cli login
npx eas-cli init
npx eas-cli build --platform android --profile preview
```
